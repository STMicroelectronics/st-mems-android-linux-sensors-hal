# Introduction

This is the documentation page for the core components of the sensors-hal iio.

# Integration

The sensorhal core uses custom defines provided by the Linux IIO drivers package for STMicroelectronics MEMS sensors.

Previously, these custom values were hardcoded into the HAL. Since kernel version 6.1, some of these values have been adopted by the IIO framework. As a result, modifications were required to meet both the updated framework and GKI requirements.

> **:warning: Important:**  
> It is recommended to always keep the IIO drivers aligned with the HAL version to ensure full compatibility.

To import these defines, copy the following two files into the `<SENSORHAL_TOPDIR>/core/include/local/` directory of the core library:

- **stm_iio_types.h**: This file (when available) is located in the `common` directory of the STMicroelectronics [Linux IIO drivers](https://github.com/STMicroelectronics/st-mems-android-linux-drivers-iio/tree/master/drivers/iio/stm/common) public GitHub repository.
- **types.h**: This file is generated by Android to remove all Linux kernel GPLv2 licensing dependencies. It is usually located in the AOSP directory: `<AOSP-TOPDIR>/bionic/libc/kernel/uapi/linux/iio/types.h`.

If these two files are not copied into the `<SENSORHAL_TOPDIR>/core/include/local/` directory of the sensor HAL library, the custom type values will default to maintain backward compatibility. However, new drivers will not be able to take advantage of some features implemented in these custom types.

# Core Library Configuration

## Core Library Build-Time Configuration

Configuration is set at compile time using `CFLAGS`. Depending on the build system you are using, you need to update the relevant file (`Android.bp`, `Android.mk`, or `CMakeLists.txt`).

**General configuration parameters:**

- `HAL_MAX_ODR_HZ`: *(int)* Maximum Output Data Rate (ODR) value used by the HAL.
- `HAL_ACCEL_MAX_RANGE_MS2`: *(int, m/s²)* Maximum measurable value for the accelerometer.
- `HAL_MAGN_MAX_RANGE_UT`: *(int, µTesla)* Maximum measurable value for the magnetometer.
- `HAL_GYRO_MAX_RANGE_RPS`: *(int, radians)* Maximum measurable value for the gyroscope.

These parameters can also be modified dynamically at runtime. Refer to the wrapper documentation for more information.

# Composite Sensors Configuration

The core library is responsible for supporting composite sensors that are realized through algorithms within proprietary ST libraries.
The release of ST proprietary libraries is subject to acceptance of a License User Agreement (LUA); for further information, please contact an STMicroelectronics sales office or representative.

## Enable/Disable Libraries

By default, mock libraries are used. You can enable or disable the following features by setting the corresponding configuration parameters:

| Parameter                                   | Description                        | Possible Values                |
|----------------------------------------------|------------------------------------|--------------------------------|
| `HAL_ENABLE_ACCEL_CALIBRATION`               | Accelerometer calibration          | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_GYRO_CALIBRATION`                | Gyroscope calibration              | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_MAGN_CALIBRATION`                | Magnetometer calibration           | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_SENSORS_FUSION`                  | Sensor fusion                      | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_TIMESYNC`                        | Sensor sample timestamp estimation | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_GYRO_TEMPERATURE_CALIBRATION`    | Gyro temperature calibration       | `0` (disabled), non-`0` (enabled) |
| `HAL_ENABLE_GEOMAG_FUSION`                   | Geomagnetic fusion                 | `0` (disabled), non-`0` (enabled) |


> **:warning: Important:**  
> The `HAL_ENABLE_TIMESYNC` configuration entry enables the sensor sample timestamp estimation feature. For this to work correctly, the `ASYNC_HW_TIMESTAMP` functionality of the IIO Linux drivers **must** also be enabled (`=y`) in the Linux kernel driver modules served by the HAL.  
> 
> **Beware:** If the HAL_ENABLE_TIMESYNC feature is enabled in the Android Sensor HAL core configuration file (such as `Android.mk` or `Android.bp`) but the corresponding driver feature is not enabled, each sensor sample timestamp will be set to zero. This will result in sample rejection by the Android sensor framework.

In the public GitHub project, mock libraries are provided to allow successful compilation.  
To use the ST proprietary libraries instead, run the provided self-extracting installer in the directory where the sensor HAL is located. This will place the proprietary library archives in the appropriate core library path. After installation, it is necessary to perform a new build and installation of the entire sensor HAL to apply the changes.
